๑. บทสรุปผู้บริหารและสภาพปัญหาเดิม (Executive Summary & Problem Statement)

สถานศึกษาในสังกัดสำนักงานคณะกรรมการการศึกษาขั้นพื้นฐาน (สพฐ.) มีภารกิจสำคัญในการบริหารจัดการเงินนอกงบประมาณประเภท "เงินบำรุงการศึกษา" และ "เงินสมาคมผู้ปกครองและครู" เพื่อสนับสนุนการจัดกระบวนการเรียนรู้และพัฒนาคุณภาพการศึกษา อย่างไรก็ดี จากการดำเนินงานที่ผ่านมา พบประเด็นปัญหาสำคัญ ๔ ประการที่ส่งผลกระทบต่อประสิทธิภาพการบริหารงานและความเสี่ยงทางวินัยการเงินการคลัง:

⚠️ ปัญหาหลักที่พบในการบริหารการเงินสถานศึกษาในปัจจุบัน:
  1. ยอดหนี้ค้างลอยจากการย้ายห้องเรียนหรือลาออก: ข้อมูลระหว่าง "งานทะเบียนนักเรียน" และ "งานการเงิน" ขาดการเชื่อมโยงแบบทันท่วงที เมื่อนักเรียนย้ายสถานศึกษา ลาออก หรือย้ายห้องเรียน ยอดหนี้เดิมยังคงค้างอยู่ในบัญชีห้องเดิม ทำให้ยอดลูกหนี้รวมของโรงเรียนคลาดเคลื่อนจากความเป็นจริง
  2. ความเสี่ยงจากการปะปนประเภทเงินและใบเสร็จ: โรงเรียนมีเงิน ๒ แหล่งหลัก คือ เงินบำรุงการศึกษา (สพฐ.) ซึ่งเป็นเงินรายได้สถานศึกษา และเงินสมาคมผู้ปกครองและครู ซึ่งเป็นเงินของนิติบุคคลภายนอก หากบันทึกรับเงินรวมกันหรือออกใบเสร็จปะปนกัน จะขัดต่อ พ.ร.บ.วินัยการเงินการคลังของรัฐ พ.ศ. ๒๕๖๑
  3. ภาระงานเอกสารซ้ำซ้อนของคุณครูที่ปรึกษา: ครูที่ปรึกษาต้องจัดพิมพ์ "บันทึกข้อความรายงานการติดตามค่าเทอม" เสนอฝ่ายบริหารด้วยโปรแกรมประมวลผลคำ (Word) ทุกสิ้นเดือนหรือสิ้นภาคเรียน ทำให้เสียเวลาการจัดการเรียนการสอนและมีความผิดพลาดของข้อมูลตัวเลขสูง
  4. ข้อจำกัดด้านงบประมาณระบบสารสนเทศ: ระบบบริหารโรงเรียนเชิงพาณิชย์ในท้องตลาดมีค่าธรรมเนียมรายปีสูง (หลักหมื่นถึงหลักแสนบาท) และไม่ตรงกับระเบียบราชการของ สพฐ. อย่างแท้จริง

วัตถุประสงค์ของการพัฒนาระบบ Hongson-SchoolPay

  • พัฒนาระบบติดตามสถานะการชำระเงินและยอดค้างชำระแบบ Real-time แยกรายห้องเรียนและแยกตามประเภทเงินได้อย่างถูกต้อง ๑๐๐%
  • จัดทำระบบ "บันทึกข้อความราชการอัจฉริยะ (1-Click Official Memo Generator)" ตามแบบฟอร์ม สพฐ. ตราครุฑ เพื่อให้ครูที่ปรึกษาสั่งพิมพ์เสนอฝ่ายบริหารได้ทันทีในคลิกเดียว
  • เชื่อมโยงวงจรชีวิตนักเรียน (ย้ายห้อง, ลาออก, พักการเรียน) กับการปรับปรุงยอดหนี้ (Debt Recalculation & Void) อัตโนมัติ ป้องกันการเกิดหนี้ค้างลอย
  • ยกระดับความโปร่งใส ตรวจสอบได้ตามระเบียบราชการ และคุ้มครองข้อมูลส่วนบุคคลตาม พ.ร.บ. PDPA พ.ศ. ๒๕๖๒
  • รันระบบบนสถาปัตยกรรม Cloud แบบ Zero Server Compute ไม่ก่อให้เกิดภาระงบประมาณค่าเช่าเซิร์ฟเวอร์แก่โรงเรียนตลอดไป

๔. สถาปัตยกรรมทางเทคนิคและกลยุทธ์ Zero Vercel Compute

ระบบ Hongson-SchoolPay เลือกใช้สถาปัตยกรรม Client-Side Heavy Single Page Application (SPA) ร่วมกับบริการ Cloud ชั้นนำของโลก เพื่อให้ระบบทำงานรวดเร็ว มีเสถียรภาพ และ **ไม่ก่อให้เกิดค่าใช้จ่ายส่วนเกิน (Zero-Cost / Free-Tier Safe)**:

องค์ประกอบ เทคโนโลยีที่เลือกใช้ หน้าที่และเหตุผลทางสถาปัตยกรรม
Code Repository & CI/CD GitHub (Private Repository) ควบคุม Source Code เวอร์ชันของระบบ มีระบบความปลอดภัยสากล และ Build Deployment อัตโนมัติ
Frontend Static Hosting Vercel Global Edge CDN ให้บริการกระจายไฟล์ Static (HTML, CSS, JS) รวดเร็วผ่าน Edge Servers ทั่วโลก โดยไม่มีการรัน Serverless Function แม้แต่ครั้งเดียว (0 Invocations)
Frontend Application React ๑๘ + TypeScript + Vite แอปพลิเคชัน SPA ที่มีความเร็วสูง เขียนด้วย TypeScript เพื่อลดข้อผิดพลาดในระดับโค้ด
Authentication Firebase Authentication เชื่อมต่อระบบยืนยันตัวตนเดิมของโรงเรียน (เช่น Google Workspace โดเมนโรงเรียน) ปลอดภัยและได้มาตรฐาน
Database & Security Cloud Firestore (NoSQL) ฐานข้อมูล Real-time มีระบบป้องกันการเข้าถึงผ่าน Firestore Security Rules ระดับ Document-Level ไม่ต้องมี API Server คั่นกลาง
File Storage Firebase Cloud Storage จัดเก็บรูปภาพสลิปโอนเงิน โดยมีระบบบีบอัดภาพหน้าบ้านก่อนอัปโหลดเพื่อประหยัดพื้นที่คลาวด์
In-Browser Processing SheetJS (XLSX) & pdfmake ประมวลผลไฟล์ Excel งานทะเบียนและแปลงเอกสาร PDF บันทึกข้อความราชการในเบราว์เซอร์ผู้ใช้โดยตรง ๑๐๐%
ทำไมระบบจึงไม่มีค่าบริการเซิร์ฟเวอร์บน Vercel (Zero Server Compute):
โดยทั่วไป การรันระบบผ่านคลาวด์มักมีค่าบริการจากจำนวน Request หรือเวลาที่เซิร์ฟเวอร์ประมวลผล แต่ Hongson-SchoolPay ถูกออกแบบให้ Vercel ทำหน้าที่เป็นเพียง "ตู้เก็บเอกสารสถิต (Static File Host)" ส่งโค้ดมาทำงานในเบราว์เซอร์ของครูและเจ้าหน้าที่ ส่วนการบันทึกข้อมูลจะติดต่อกับ Google Firebase โดยตรง ทำให้โควตา Serverless Compute บน Vercel มีค่าเป็น ๐ ครั้งตลอดไป

๖. การวิเคราะห์ต้นทุน ความคุ้มค่า และค่าใช้จ่ายในอนาคต (Future Cost Analysis)

หนึ่งในข้อพิจารณาสำคัญของฝ่ายบริหารคือความคุ้มค่าและภาระผูกพันทางการเงินในอนาคต ตารางด้านล่างแสดงการเปรียบเทียบโควตาบริการฟรี (Free Tier) กับการใช้งานจริงของโรงเรียนขนาด ๑,๕๐๐ - ๒,๕๐๐ คน:

บริการ Cloud โควตาฟรี (Free Tier) ปริมาณใช้งานจริงของโรงเรียน สถานะค่าใช้จ่าย
Vercel Bandwidth 100 GB ต่อเดือน ประมาณ 5 - 10 GB ต่อเดือน ฟรี ($0)
Vercel Function Compute 100,000 executions 0 ครั้ง (ไม่มีเซิร์ฟเวอร์บน Vercel) ฟรี ($0)
Firebase Firestore Reads 50,000 reads ต่อวัน ประมาณ 8,000 - 15,000 reads ต่อวัน ฟรี ($0)
Firebase Firestore Writes 20,000 writes ต่อวัน ประมาณ 500 - 1,500 writes ต่อวัน ฟรี ($0)
Firebase Storage 5,000 MB (5 GB รวม) ปีละ ~1,000 MB (บีบอัดรูปเหลือ 100KB) ฟรี ($0) นาน 4-5 ปี
Firebase Authentication ไม่จำกัดจำนวนบัญชี ครูและบุคลากร 100 - 200 บัญชี ฟรี ($0)

การวิเคราะห์ค่าใช้จ่ายที่อาจเกิดขึ้นในอนาคตและแนวทางป้องกัน (Worst-case Scenarios)

ปัจจัยเสี่ยงที่อาจทำให้เกิดค่าใช้จ่ายในอนาคต (Potential Future Cost Drivers):
  1. กรณีรูปภาพสลิปสะสมเกิน ๕ GB ใน Firebase Cloud Storage (หลังจากใช้งานไป ๔-๕ ปี):
    • แนวทางป้องกันที่ ๑ (ค่าใช้จ่าย ๐ บาท): เมื่อสิ้นสุดแต่ละปีการศึกษาและผ่านการตรวจสอบบัญชีจาก สตง. แล้ว ฝ่ายการเงินสามารถกดปุ่ม "Export & Archive ข้อมูลเก่า" บันทึกลง External Harddisk ของโรงเรียน และทำการลบรูปสลิปเก่าที่มีอายุเกิน ๒ ปีออกจากระบบ ทำให้พื้นที่ไม่เคยเต็ม
    • แนวทางป้องกันที่ ๒ (กรณีต้องการเก็บบน Cloud ต่อไป): ค่าบริการ Cloud Storage ส่วนเกินคิดที่ 0.026 USD ต่อ GB ต่อเดือน (หรือประมาณ ๙ - ๑๐ บาทต่อ ๑ GB ต่อเดือน) คิดเป็นค่าใช้จ่ายไม่เกิน ๑๐๐ - ๑๕๐ บาทต่อปี ซึ่งอยู่ในวิสัยที่สถานศึกษาบริหารจัดการได้
  2. ค่าโดเมนเนมของโรงเรียน (Domain Name):
    • โรงเรียนสังกัด สพฐ. มีโดเมนทางการ .ac.th อยู่แล้ว สามารถสร้าง Subdomain เช่น schoolpay.school.ac.th ชี้มายัง Vercel ได้โดยตรง ไม่มีค่าใช้จ่ายเพิ่มแม้แต่บาทเดียว
